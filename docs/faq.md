# частые вопросы

## установка и версии

**какой тег ставить для исправлений этого checkout?** обновлённый выпуск ещё не опубликован, текущий checkout не является тегом `v0.2.0`. сначала открой [выпуски](https://github.com/narimanisakhanov-creator/omp-settings-ru/releases) и устанавливай только опубликованный проверенный тег, как указано в [README](../README.md#установка).

**менеджер не находит Bun.** проверь наличие Bun в PATH процесса, запускающего `omp plugin`; версии проекта указаны в manifest. не удаляй весь кэш и не меняй глобальное окружение ради неподтверждённой причины.

**панель осталась английской.** сначала выясни версию OMP и загруженную копию плагина через `omp --version` и `omp plugin list --json`. опубликованный старый тег и исправленный checkout имеют разные границы совместимости. затем открой новую сессию и `/settings`; сохрани предупреждение, если оно есть.

**как проверить checkout отдельно?** используй одноразовый профиль и очищенное окружение по [CONTRIBUTING](../CONTRIBUTING.md#проверка-установленного-хоста), не рабочий профиль с личными ключами.

## язык и поведение

**переключил язык, но панель не изменилась.** закрой `/settings` через Esc и открой заново — панель строит строки при открытии.

**почему вкладки и группы на английском?** переводятся отображаемые поля настроек и статические подписи вариантов; вкладки, группы, подсказки навигации и динамические списки остаются у хоста. см. [архитектуру](architecture.md).

**часть строк на английском.** неизвестный путь или изменившийся источник не получает старый перевод. сообщи версию хоста, ОС и название настройки без личных данных.

**`/settings-language` без аргументов не открыл выбор.** команда вводится из основного промпта, не строки поиска панели. закрой панель и повтори.

**как вернуть английский?** `/settings-language en`, затем заново открой `/settings`. язык не сохраняется в конфиг; следующая основная сессия с плагином начинает с русского.

**как удалить?** сначала верни английский в текущей сессии, затем `omp plugin uninstall omp-settings-ru` и запусти новую сессию. при загрузке через `-e` убери этот аргумент.

## границы проверки

**проверен ли Linux/macOS?** есть проверки извлечённых исходников, но нет прогона установленной панели. package registry на Windows и installed-panel smoke — отдельные уровни доказательств.

**неизвестная версия обязательно отклоняется?** нет: исправленный runtime проверяет структуру и выбирает перевод по точному пути, хешу источника и платформе. знакомая строка может перевестись; это не обещание поддержки неизвестного хоста. некорректный реестр или небезопасные дескрипторы приводят к отказу.

**повлияет ли перевод на модели и конфиги?** runtime перевода меняет только отображаемые метаданные в памяти. значения и обработчики остаются у OMP; сам OMP может сохранять настройки при твоих действиях в панели. см. [SECURITY](../SECURITY.md).
