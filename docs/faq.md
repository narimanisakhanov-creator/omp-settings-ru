# частые вопросы

## установка и версии

### как установить плагин?

один штатный путь — marketplace OMP с каталогом `marketplace.json` из выпуска. три команды по порядку, включая явное включение общего `auto`, и предупреждение о его области — в [README](../README.md#установка). legacy npm-managed GitHub-установки больше нет: `private:true`, `omp.extensions`, архив и `SHA256SUMS` описывают упаковку и происхождение релиза, а запуск `-e` из checkout — только разработку.

### какой тег ставить для исправлений этого checkout?

выбирать тег вручную не нужно: каталог закрепляет release commit полным `source.sha` и тегом `source.ref`, а `releases/latest` отдаёт последний проверенный выпуск. сверяй номер на странице [выпусков](https://github.com/narimanisakhanov-creator/omp-settings-ru/releases). checkout не является выпуском.

### менеджер не находит Bun.

проверь наличие Bun в PATH процесса, запускающего `omp plugin`; версии проекта указаны в manifest. не удаляй весь кэш и не меняй глобальное окружение ради неподтверждённой причины.

### панель осталась английской.

сначала выясни версию OMP и загруженную копию плагина через `omp --version` и `omp plugin list --json`. установленный выпуск мог не обновиться: `auto` освежает каталог не при каждом запуске, а после 24 часов в осмотренном OMP 18.8.7, и ошибки startup updater подавляет хост. немедленная проверка — команды в [README](../README.md#обновление), затем открой новую сессию и `/settings`; сохрани предупреждение, если оно есть.

### как проверить checkout отдельно?

используй одноразовый профиль и очищенное окружение по [CONTRIBUTING](../CONTRIBUTING.md#проверка-установленного-хоста), не рабочий профиль с личными ключами. запуск `-e` относится к разработке и не является установкой.

### у меня осталась установка `github:...#v<version>`. что делать?

это legacy npm-установка; публично поддерживается только marketplace, и второй канал рядом не ставится. одноразовый state-preserving переход из одной legacy npm user-установки описан в [CONTRIBUTING](../CONTRIBUTING.md#переход-на-marketplace): обратный переход `--to npm` отклоняется, а project-дубли и explicit roots должны быть убраны до запуска. `uninstall` для перехода не годится — он стирает собственные plugin settings/features. уже установленный marketplace-канал перехода не требует.

### auto обновляет только перевод?

нет: `marketplace.autoUpdate=auto` — общая настройка OMP для всех marketplace-плагинов пользователя и активного проекта, не только перевода. `notify` не устанавливает обновления, `off` не проверяет. это не project ReleasePin/SHA256SUMS gate: если новый кандидат не прошёл проверки, `latest` остаётся прошлый проверенный выпуск. `auto` не гарантирует немедленное обновление и не заменяет сетевую ошибку. немедленная проверка — в [README](../README.md#обновление).

### где лежит каталог marketplace?

каталог — ассет `marketplace.json` внутри GitHub-выпуска, а не ветка:

```text
https://github.com/narimanisakhanov-creator/omp-settings-ru/releases/latest/download/marketplace.json
```

он закрепляет release commit тегом `source.ref` и полным `source.sha`; не подменяй source движущимся `main`.

### я добавлял старый каталог из ветки `marketplace`.

этот URL больше не обслуживается. убери старое имя и добавь новое — состояние плагина при этом сохраняется:

```text
omp plugin marketplace remove omp-settings-ru
omp plugin marketplace add https://github.com/narimanisakhanov-creator/omp-settings-ru/releases/latest/download/marketplace.json
omp plugin marketplace update omp-settings-ru
```

повторный `add` того же имени с другим URL отклоняется, поэтому шаг `remove` обязателен. не используй `uninstall` ради перехода: он стирает собственные plugin settings/features.

## язык и поведение

### переключил язык, но панель не изменилась.

закрой `/settings` через Esc и открой заново — панель строит строки при открытии.

### почему вкладки и группы на английском?

переводятся отображаемые поля настроек и статические подписи вариантов; вкладки, группы, подсказки навигации и динамические списки остаются у хоста. см. [архитектуру](architecture.md).

### часть строк на английском.

неизвестный путь или изменившийся источник не получает старый перевод. сообщи версию хоста, ОС и название настройки без личных данных.

### `/settings-language` без аргументов не открыл выбор.

команда вводится из основного промпта, не строки поиска панели. закрой панель и повтори.

### как вернуть английский?

`/settings-language en`, затем заново открой `/settings`. язык не сохраняется в конфиг; следующая основная сессия с плагином начинает с русского.

### как удалить?

сначала верни английский в текущей сессии, затем выполни `omp plugin uninstall omp-settings-ru@omp-settings-ru` и запусти новую сессию; последовательность — в [README](../README.md#язык-и-удаление). для отключения без потери state используй `omp plugin disable omp-settings-ru@omp-settings-ru`. при загрузке через `-e` убери этот аргумент. команда с этим ID относится к marketplace-установке: оставшуюся legacy npm-установку сначала переведи по [CONTRIBUTING](../CONTRIBUTING.md#переход-на-marketplace).

## границы проверки

### проверен ли Linux/macOS?

да: текущий CI прогоняет нативную панель на Windows, Linux и macOS для всех четырёх версий — таблица и источник run в [README](../README.md#проверенная-совместимость-checkout). это проверка указанных байтов checkout, не опубликованного тега. метаданные реестра, исторические локальные прогоны и per-commit CI — разные уровни доказательств ([CONTRIBUTING](../CONTRIBUTING.md#матрица-и-peer-диапазон)).

### неизвестная версия обязательно отклоняется?

нет: runtime проверяет структуру и выбирает перевод по точному пути, хешу источника и платформе. знакомая строка может перевестись; это не обещание поддержки неизвестного хоста. некорректный реестр или небезопасные дескрипторы приводят к отказу.

### повлияет ли перевод на модели и конфиги?

runtime перевода меняет только отображаемые метаданные в памяти. значения и обработчики остаются у OMP; сам OMP может сохранять настройки при твоих действиях в панели. см. [SECURITY](../SECURITY.md).
