# архитектура

Плагин переводит не панель, а данные, из которых панель строится. Штатная панель `/settings` при каждом открытии читает живые определения настроек хоста (`orderedSettings()`); плагин подменяет в них только отображаемые поля и возвращает всё обратно по требованию.

```mermaid
flowchart TD
    A[Основная сессия OMP] --> B[host-adapter: живые метаданные]
    B --> C{compatibility: структура реестра}
    C -->|несовместимо| D[английский + русское предупреждение]
    C -->|совместимо| E[точный путь + sourceHash + платформа: план мутаций]
    E --> F{все дескрипторы записываемы?}
    F -->|нет| G[атомарный отказ, ничего не тронуто]
    F -->|да| H[русские метаданные в памяти]
    H --> I[штатная панель /settings]
    H --> J[/settings-language en или shutdown main]
    J --> K[восстановление исходных дескрипторов]
```

## что именно подменяется

Для каждой настройки из единого каталога данных `src/translations/ru-catalog.json` (ключ — полный путь настройки) выбирается вариант с точным хешем исходных метаданных и подходящей платформой. `ru.ts` — только типизированный JSON-адаптер; сборки вариантов по версиям в runtime нет:

- `ui.label`, `ui.description`, `ui.warning` — целиком;
- `ui.options[i].label/description` — через копии объектов, чтобы не задеть метаданные, общие с автодополнением команд;
- описания с живыми подсказками клавиш (`{escape}`, `{accept}` …) — через getter поверх проверенного английского шаблона: актуальные клавиши всегда берёт хост, а не перевод.

Не трогаются: `id`, `type`, `default`, `values`, обработчики, вкладки, группы, пути, имена моделей и провайдеров, секреты.

## почему перевод безопасен

1. **план до записи.** Все мутации собираются заранее; первая же незаписываемая — отказ целиком, без частичного применения.
2. **хеш источника.** Варианты сохраняют SHA-256 нормализованных исходных метаданных и проверенное происхождение. Старые версии выбирают старый вариант, новые — отдельно проверенный. Неизвестный путь или хеш остаётся английским; структурный fallback не обещает поддержку неизвестного установленного хоста.
3. **владение дескрипторами.** Восстановление возвращает только то, что плагин сам записал (сравнение полных дескрипторов, а не значений). Поздние правки другого расширения переживают восстановление.
4. **незавершённый откат не теряется.** Если откат упёрся в отказ, плагин удерживает план восстановления: `en` и завершение сессии повторяют его, а не сообщают ложный успех.

## кто владеет языком

Только основная сессия (`agent.kind === "main"`). Переходы сериализуются в очередь; дочерний агент не может применить или снять перевод родителя. Выбор языка живёт в памяти процесса и никуда не записывается — следующая сессия стартует на русском, пока плагин установлен.

## сопровождение при обновлении OMP

`test/fixtures/host-snapshots/<версия>-<платформа>.json` фиксирует исходные метаданные; `test/fixtures/host-snapshots/supported-hosts.json` связывает пары с пакетами, платформами и `sha256` снимков плюс отдельными installed receipts. Это единственный отслеживаемый экземпляр снимков: `baseline/` в checkout остаётся локальным каталогом ручного экспорта и игнорируется Git, а путь к данным задаёт `scripts/maintenance/paths.ts`, поэтому писатель и читатели не расходятся. Три уровня доказательств — метаданные реестра, исторические локальные прогоны и per-commit native CI — не заменяют друг друга; определения в [CONTRIBUTING.md](../CONTRIBUTING.md#матрица-и-peer-диапазон). После обновления хоста сопровождающий сравнивает added/removed/changed, сохраняет исторические варианты и отдельно проверяет native panel. Порядок работы — в [сопровождении](maintenance.md).

Каталог кандидата читается строгим JSON-парсером без выполнения его кода: повторные ключи, неизвестные поля, некорректные платформы/версии и пересекающиеся source/platform identities отклоняются. Историческая сохранность проверяется отдельно по переводу, каждой платформе и `observedIn`; добавлять наблюдения можно, терять — нельзя. `translationFieldsHash` исключает `sourceHash`, `platforms`, `observedIn`, но сохраняет порядок display-полей. Новая identity или расширение платформ не требуют review proof: при `semanticReview: "disabled"` `verifyVariantReviews` не выдаёт для них `unreviewed-*`, а исторические строки `independently-confirmed` не переписываются — их `translationHash`, `comparison` и `evidence` сверяются с неизменяемой историей. Изменение единственного JSON-файла не меняет проверку неизменённых строк.

Единственное историческое соответствие маркера — `<level>` → `<уровень>` в description двух уже выпущенных вариантов `statusLine.compactThinkingLevel`. Оно привязано к двум точным sourceHash/translationHash из `variant-review.json` неизменяемого коммита `370b2028798c5f5c1da797e0d321191ae1780d88`; другой путь, поле, источник, перевод или добавленный маркер исключения не получают.
