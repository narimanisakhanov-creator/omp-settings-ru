# участие и сопровождение

## окружение

Bun 1.3.14, TypeScript 5.9.2, пакеты хоста 18.8.0; версии и транзитивные зависимости закреплены `bun.lock`. runtime плагина не должен импортировать установленную в проекте копию вместо живого реестра скомпилированного OMP. `host-adapter.ts` использует предоставляемые хостом модули внутри границы безопасного отказа.

```powershell
bun install --frozen-lockfile --ignore-scripts
bun run check
```

сначала доменная проверка ошибки, затем исправление. тестируем поведение, инварианты и границы, а не совпадение формулировок. инфраструктурные скрипты и smoke отдельно; дополнительные mock/integration-слои не нужны.

## обновление OMP

1. выполни `bun scripts/upgrade-host.ts <version|latest>`. скрипт обновляет пины `@oh-my-pi/*`, lockfile, экспортирует baseline новой версии и печатает drift-отчёт в `upgrade-report.md`. не расширяй совместимость заранее.
2. переведи новые названия, описания, предупреждения и статические options вручную. ключ варианта — оригинальный `value`, не русский label.
3. проверь каждую изменившуюся английскую строку, затем обнови её `sourceHash` только у изменившихся строк. не переписывай хеши автоматически, чтобы скрыть drift. изменившийся источник не должен получать старый перевод.
4. динамические описания: обнови проверенный английский шаблон в `source-templates.ts`, тот же `descriptionSource` в каталоге и русский текст с теми же `{placeholder}`. при несовпадении шаблона сохраняем английский getter.
5. извлеки baseline на каждой реально проверяемой ОС. метаданные настроек Linux (`.settings`) эквивалентны Windows; darwin добавляет вариант `apple` у `spelling.autocomplete`. прогон Linux/macOS не заявляется без отдельной проверки.
6. прогони `bun run check`, затем установленный OMP новой версии в одноразовом HOME/профиле: загрузка, `/settings`, русский поиск, безопасное bool/enum-изменение, en/ru, выбор без аргументов, новая сессия без расширения. не используй реальные ключи и назначения моделей.
7. только после успешного ручного прогона установленной панели обнови `compatibility.ts`, baseline каталога и таблицу совместимости README. успешный CI этот прогон не подменяет. версию плагина повышаем отдельно по semver.

`.github/workflows/upstream-watch.yml` по расписанию резолвит latest upstream и открывает PR `upgrade: OMP <version>` с отчётом и чеклистом. workflow проверяет входную версию до передачи её в shell-команды. новый upgrade branch публикуется обычным non-force push; существующая ветка без PR сохраняется и используется только для создания отсутствующего PR, а ветка с уже существующим PR не изменяется и не редактируется. подготовка и baseline работают с `contents: read`; публикация получает `contents: write` и `pull-requests: write`. если автоматическая проверка завершается с ошибкой, её код возврата и вывод явно приложены к отчёту; это не объявляется успешной проверкой. `.github/workflows/release.yml` по тегу `v*` прогоняет `bun run check`, собирает архив и `SHA256SUMS`, публикует GitHub Release и двигает ветку `stable`.

## устройство

- `host-types.ts`, `source.ts`: минимальная схема живых метаданных и SHA-256 нормализованного источника;
- `apply-translations.ts`: полный план дескрипторов, отображаемые копии options, атомарный отказ/откат и восстановление только собственных записей;
- `language-controller.ts`: последовательные переходы; только `agent.kind === "main"`;
- `index.ts`: события и команда, без доступа к конфигам;
- `report.ts`: детерминированные покрытие и drift;
- `scripts/smoke-extension.ts`: три ru/en round trip на настоящем реестре;
- `scripts/smoke-panel*.ts`: настоящий компонент панели и обработчики настроек в очищенном временном окружении;
- `test/`: доменные регрессии; fixture-объекты моделируют семантику метаданных, не эхо mock-обработчиков.

не переносить Stats, PATH-установщики, autocomplete, сетевые клиенты или чтение сессий. сохранять MIT-атрибуцию Elazer.

## выпуск

- `bun install --frozen-lockfile --ignore-scripts`; `bun run check`;
- проверить состав: `npm.cmd pack --dry-run --json`; распространяются только manifest, `src`, README/CONTRIBUTING/CHANGELOG/LICENSE/THIRD_PARTY_NOTICES/SECURITY;
- `bun run release:check` проверяет разрешённые файлы и признаки личных путей/секретов;
- read-only ревью механизма, каталога, лицензий и доказательств запуска; исправить обязательные замечания;
- сохранить реальные результаты в changelog, не объявлять непроверенные версии/ОС поддерживаемыми;
- не расширять совместимость заранее: `compatibility.ts` бампать только после ручного прогона установленной панели; успешный CI этот прогон не подменяет;
- получить отдельное разрешение владельца на коммит и на создание/публикацию GitHub-репозитория;
- добавить URL репозитория в manifest; сохранять `private`, пока npm-публикация не запланирована; tag/release согласовать с версией; старые теги не переписывать;
- проверить установку и удаление штатным менеджером в одноразовом профиле.

публичный репозиторий: https://github.com/narimanisakhanov-creator/omp-settings-ru. CI Windows/Linux запускает те же проверки; успешный CI не подменяет запуск установленной панели. release archive и SHA256SUMS прикладываются к GitHub Release. релизный workflow `.github/workflows/release.yml` по тегу `v*` выполняет `bun run check`, собирает архив и `SHA256SUMS`, публикует GitHub Release и двигает ветку `stable`.
