# участие и сопровождение

## окружение

Bun 1.3.14, TypeScript 5.9.2, пакеты хоста 18.6.1; версии и транзитивные зависимости закреплены `bun.lock`. runtime плагина не должен импортировать установленную в проекте копию вместо живого реестра скомпилированного OMP. `host-adapter.ts` использует предоставляемые хостом модули внутри границы безопасного отказа.

```powershell
bun install --frozen-lockfile --ignore-scripts
bun run check
```

сначала доменная проверка ошибки, затем исправление. тестируем поведение, инварианты и границы, а не совпадение формулировок. инфраструктурные скрипты и smoke отдельно; дополнительные mock/integration-слои не нужны.

## обновление OMP

1. в отдельном checkout закрепи новую версию всех прямых пакетов хоста в `package.json`; обнови lockfile штатным Bun. не расширяй совместимость заранее.
2. извлеки только исходные метаданные:

   ```powershell
   bun run source:export baseline/<версия>-win32.json
   bun run drift:check
   bun run coverage:check
   ```

   `source:export` читает реестр определений, не конфиг и не значения. прежде чем заменить старую baseline, сохрани её и сравни вывод: added/removed/changed.
3. `src/translations/ru-part-{1,2,3}.ts` содержат записи по полному ID; `ru.ts` объединяет их и полные платформенные overrides. переведи все новые названия, описания, предупреждения и статические options. ключ варианта — оригинальный `value`, не русский label.
4. проверь каждую изменившуюся английскую строку, затем обнови её `sourceHash`. не переписывай хеши автоматически, чтобы скрыть drift. изменившийся источник не должен получать старый перевод.
5. динамические описания: обнови проверенный английский шаблон в `source-templates.ts`, тот же `descriptionSource` в каталоге и русский текст с теми же `{placeholder}`. при несовпадении шаблона сохраняем английский getter.
6. извлеки baseline на каждой реально проверяемой ОС. нынешние linux/darwin baseline выведены из исходных веток 18.6.1 на Windows; это **не** свидетельство прогона Linux/macOS. единственная платформенная ветка списка настроек — вариант `apple` у `spelling.autocomplete` на darwin.
7. прогони `bun run check`, затем установленный OMP новой версии в одноразовом HOME/профиле: загрузка, `/settings`, русский поиск, безопасное bool/enum-изменение, en/ru, выбор без аргументов, новая сессия без расширения. не используй реальные ключи и назначения моделей.
8. только после успешного запуска обнови `compatibility.ts`, baseline каталога и таблицу совместимости README. версию плагина повышаем отдельно по semver.

## устройство

- `host-types.ts`, `source.ts`: минимальная схема живых метаданных и SHA-256 нормализованного источника;
- `apply-translations.ts`: полный план дескрипторов, отображаемые копии options, атомарный отказ/откат и восстановление только собственных записей;
- `language-controller.ts`: последовательные переходы; только `agent.kind === "main"`;
- `index.ts`: события и команда, без доступа к конфигам;
- `report.ts`: детерминированные покрытие и drift;
- `scripts/smoke-extension.ts`: три ru/en round trip на настоящем реестре;
- `scripts/smoke-panel*.ts`: настоящий компонент панели и обработчики настроек в очищенном временном окружении;
- `test/`: доменные регрессии; fixture-объекты моделируют семантику метаданных, не эхо mock-обработчиков.

не переносить Stats, PATH-установщики, autocomplete, сетевые клиенты или чтение сессий. сохранять MIT-атрибуцию Elazer.

## выпуск

- `bun install --frozen-lockfile --ignore-scripts`; `bun run check`;
- проверить состав: `npm.cmd pack --dry-run --json`; распространяются только manifest, `src`, README/CONTRIBUTING/CHANGELOG/LICENSE/THIRD_PARTY_NOTICES/SECURITY;
- `bun run release:check` проверяет разрешённые файлы и признаки личных путей/секретов;
- read-only ревью механизма, каталога, лицензий и доказательств запуска; исправить обязательные замечания;
- сохранить реальные результаты в changelog, не объявлять непроверенные версии/ОС поддерживаемыми;
- получить отдельное разрешение владельца на коммит и на создание/публикацию GitHub-репозитория;
- добавить URL репозитория в manifest; сохранять `private`, пока npm-публикация не запланирована; tag/release согласовать с версией. не переписывать старые теги;
- проверить установку и удаление штатным менеджером в одноразовом профиле.

публичный репозиторий: https://github.com/narimanisakhanov-creator/omp-settings-ru. CI Windows/Linux запускает те же проверки; успешный CI не подменяет запуск установленной панели. release archive и SHA256SUMS прикладываются к GitHub Release.
